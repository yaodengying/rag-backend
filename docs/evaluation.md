# 离线评估（RAGAS）

> 一句话：`scripts/evaluate_rag.py` 拿一份带标准答案的问答集去**考**真实问答链路，
> 用 RAGAS 打语义分、用「文件名 + 页码」比对打确定性召回分，结果落成四份文件。

评估代码在 `scripts/rag_eval/`，数据集在 `eval/dataset/`，结果在 `eval/results/<时间戳>/`。
它是**开发期工具**，不进 `app/`——线上服务不该依赖指标库。

---

## 一、评什么、不评什么

| 指标 | 判据 | 需要 | 谁算 |
|---|---|---|---|
| `faithfulness`（忠实度） | 回答里的每句话能否被检索到的上下文支持 | 裁判 LLM | RAGAS |
| `answer_relevancy`（答案相关性） | 由回答反推问题，与原问题的语义相似度 | 裁判 LLM + 向量模型 | RAGAS |
| `context_recall`（上下文召回率） | 标准答案的信息点有多少被上下文覆盖 | 裁判 LLM + 标准答案 | RAGAS |
| `context_precision`（上下文精确率） | 上下文里有多少条真正有用 | 裁判 LLM + 标准答案 | RAGAS |
| **命中率 Hit@k** | 期望来源（文件名+页码）是否出现在引用里 | 无（纯比对） | 本项目 |
| **页码级召回率** | 命中的期望来源数 / 期望来源总数 | 无 | 本项目 |
| **MRR** | 首个命中来源名次的倒数 | 无 | 本项目 |
| **拒答正确率** | 语料里没有答案的题，是否真的拒答 | 无 | 本项目 |

两类指标不能互相替代：

- RAGAS 的 `context_recall` 是**语义**覆盖度，回答"资料够不够回答问题"；
- 本项目的页码召回是**溯源**准确度，回答"引用的那一页是不是真的那一页"。

本项目的卖点是页码级溯源，而 RAGAS 没有页码概念——这就是为什么要自己算第二组。
第二组不调模型、结果可复现，做基线对比时优先看它。

**不评估的部分**（避免误读）：
- 多轮对话的指代消解（数据集全是单轮）；
- 流式链路的 SSE 事件时序（`scripts/verify_upload_flow.py` 与前端 E2E 负责）；
- 上传/切分/入库链路（`scripts/check_loading.py`、`check_splitting.py` 负责）。

## 二、数据集（`eval/dataset/qa_dataset.jsonl`）

一行一题，字段：

```json
{
  "id": "q01",
  "kb_id": "3385b243-…",
  "answerable": true,
  "question": "产品保修期是多久？",
  "reference": "产品自客户签收之日起提供保修 24 个月。",
  "reference_contexts": ["售后服务制度\n第一条 保修范围\n…"],
  "expected_sources": [{"filename": "售后服务制度.pdf", "page": 1}]
}
```

| 字段 | 作用 | 写错的后果 |
|---|---|---|
| `reference` | RAGAS 判 `context_recall` / `context_precision` 的基准 | 写了语料里没有的说法 → 指标无意义 |
| `expected_sources` | 确定性召回的期望（文件名 + 1 起页码） | 页码写错 → 召回率假阴性 |
| `answerable` | `false` 表示语料里没答案、**应当拒答** | 混进 RAGAS 均值会让指标虚高 |

`answerable=false` 的题**不进** RAGAS 聚合：RAGAS 没有"应当拒答"的度量，
把一句"无法从知识库中找到答案"送进 faithfulness，天然拿满分。

构造原则（当前 18 题 = 16 可答 + 2 应拒答）：

1. **答案必须在语料里能找到原文**，标准答案照着原文写，不做同义扩写；
2. **页码可核对**：`expected_sources` 的页码来自解析层的 `Page.page_no`；
3. **留一组应拒答题**：用来量"会不会瞎编"，这比多刷几道可答题更有信息量；
4. 覆盖不同格式（PDF 多页 / TXT 单页）与不同知识库。

> 当前语料很小（一个 4 页 PDF + 两个 txt），检索几乎不会跑偏，
> 绝对分数偏乐观。它的用途是**同一个库的版本间对比**，不是对外宣称能力。

## 三、跑一次

在项目根目录（`.env` 按相对路径加载）：

```bash
cd H:\work\rag-backend

# 全量（18 题，含 RAGAS；本机 7B 约 5~6 分钟）
.venv\Scripts\python.exe scripts\evaluate_rag.py

# 只算确定性检索指标：不调裁判模型，几秒出结果
.venv\Scripts\python.exe scripts\evaluate_rag.py --no-ragas

# 试跑 / 挑题 / 指定输出目录
.venv\Scripts\python.exe scripts\evaluate_rag.py --limit 3
.venv\Scripts\python.exe scripts\evaluate_rag.py --ids q01,q17
.venv\Scripts\python.exe scripts\evaluate_rag.py --metrics faithfulness,answer_relevancy ^
    --out eval\results\baseline

# 只校验数据集，不跑模型
.venv\Scripts\python.exe scripts\evaluate_rag.py --dry-run
```

依赖：Milvus（检索）+ Ollama（裁判与回答）+ 本地 BGE 权重。**不需要**先起 FastAPI——
评估在进程内直调服务层，省掉 SSE 与网络往返。

退 出 码：`0` 全绿；`1` 有样本失败或某指标一题都没算出来；`2` 环境/输入问题。

## 五、五个容易误读的口径

1. **裁判就是被测模型。** RAGAS 用 `.env` 里的同一个 LLM 判分。7B 自评偏宽松，
   绝对分数只适合**横向比较**（换配置前后），不适合对外宣称。
2. **`valid < total` 不是 0 分。** 模型输出无法解析时该题记 NaN，已排除在均值外。
   `report.md` 里每项都标了有效样本数。
3. **`answer_relevancy = 0` 要回看原文。** 该指标先让裁判判断回答是否"含糊其辞"，
   全判为是则直接 0。本地 7B 偶有误判（切题回答被判 0），单题结论以
   `samples.jsonl` 的原文为准。
4. **答出率的分母不含失败样本。** 调用失败是环境故障，不是模型拒答；
   两者混在一个比率里会让"Ollama 挂了"看起来像"模型不肯回答"。
5. **两套召回率不是一回事。** 见第一节末尾。

## 六、环境与已知问题

**Python 3.14 + langchain-community 0.4 + ragas 0.4.3 的兼容性**

`import ragas` 会失败：它在 `ragas/llms/base.py` 顶层导入
`langchain_community.chat_models.vertexai`，而该模块在 community 0.4 已被移除
（Vertex 集成迁到独立包）。`scripts/rag_eval/compat.py` 在 import 前注入一个空壳模块，
理由与安全性见该文件顶部注释。

**不要直接 `pip install ragas`**

依赖解析会把 `openai` 3.28 → 1.109、`langchain-openai` 1.7 → 1.1.9 一起降级
（为满足 `instructor` 的约束），而生产链路的 `app/infrastructure/llm.py` 正走
langchain-openai。安装时用 `--no-deps` 再单独补缺的包：

```bash
.venv\Scripts\python.exe -m pip install --no-deps \
    ragas instructor appdirs diskcache nest-asyncio docstring_parser \
    -i https://pypi.tuna.tsinghua.edu.cn/simple
```

- 不装 `scikit-network`：它只被 `ragas/testset/graph.py`（合成数据集生成）使用，
  且 Python 3.14 上没有预编译轮子，现场编译会失败。
- `rich` 保持 15.x：`instructor` 声明 `<15`，但只在 CLI 用到，不影响指标计算。

**Ollama 的两处缺口**

| 现象 | 原因 | 处理 |
|---|---|---|
| `LLM returned 1 generations instead of requested 2` | OpenAI 兼容端点不支持 `n>1` | 适配层声明 `bypass_n=True` |
| `Unexpected type for token usage` 警告刷屏 | 响应不带 usage | 入口脚本过滤该警告 |

**同一进程里连续调用两次 `evaluate()`** 会报 `RuntimeError: Event loop is closed`
（ragas 的 executor 复用了已关闭的事件循环）。评估入口只调一次；若要在一个进程里
跑多组指标，请分进程。

## 八、提示词迭代：四轮回落与最终形态（2026-10-18）

防幻觉提示词改了三稿都不如基线，第四稿才同时拿下忠实度与命中率。全过程留在这里，
因为**每一轮失败的原因都不一样，而且都反直觉**。原始结果目录：

| 版本 | 提示词要点 | 忠实度 | 相关性 | 命中率 | 答出率 | 结果目录 |
|---|---|---|---|---|---|---|
| 基线 | 一句「只依据资料、答不了就拒答」 | 0.9024 | 0.7868 | 1.0000 | 1.0000 | `20261017-165411` |
| v1 | 6 条编号禁令 + 条件句写来源标注 | 0.8594 | 0.6301 | **0.9375** | 0.9375 | `20261017-174105` |
| v2 | +「完全无关才拒答」+「不是拒答的理由」 | 0.9062 | 0.6493 | **0.9375** | 0.9375 | `20261017-174728` |
| v3 | 删掉行内 `(来源：[n])` 要求 | **0.7812** | 0.6390 | 1.0000 | 1.0000 | `20261017-175335` |
| v3b | 去掉「不要用『资料未说明』代替」的歧义句 | 0.8576 | 0.6468 | 1.0000 | 1.0000 | `20261017-175839` |
| **最终** | 「允许留白，**但不给句式**」 | **0.9896** | 0.7466 | 1.0000 | 1.0000 | `20261017-180621` |

> ⚠️ 基线那一行是**去重修复之前**跑的：同一个 txt 被重复上传，`q10` 的上下文是 4 条**逐字相同**的
> 片段。所以 `context_recall` 1.0000 → 0.9375 的差不是提示词造成的（去重后 `q10` 只剩 1 条），
> 其余指标不受影响。

### 8.1 v1：禁令生效了，但「该答的不答」

加严之后 q02（哪些情况不在保修范围内？）**上下文完全正确、那句话就摆在资料里**，模型照抄了
拒答话术——命中率与答出率同时掉到 0.9375。原因是正面要求写成了**条件句**：
「若参考资料带有来源标注，则在回答里标注 `(来源：[n])`」。7B 把「若…则…」当成**前提不成立**，
于是连带整段约束都不执行（16/16 道题都没标序号）。

**教训：正面要求必须是无条件祈使句。** 把"要不要做"留给模型判断，它会在两个方向上都出错。

### 8.2 v2：忠实度回来了，q02 仍然拒答

补上「只有**完全无关**才拒答」「资料简短、只覆盖一部分都不是拒答的理由」后，忠实度 0.9062
（略高于基线），但 q02 还是拒。说明措辞加强到这一层已经到底了——**问题不在措辞强度**。

### 8.3 v3：删掉一条「模型必然违反」的指令

行内序号要求试过三种写法（条件句 / 无条件祈使句 / 加剧禁令），遵守率分别是 16/16 不写、
13/18 不写，始终不稳定。而结构化 `citations` 已经给了文件名 + 页码，行内序号只是锦上添花。
**留一条必然被违反的指令，只会让"提示词遵守度"这个信号永久噪音化**，于是整段删掉，
`_audit_answer()` 也不再报"未标注序号"，只报**序号越界**（引用了本轮不存在的第 5 条资料）。

代价：忠实度掉到 0.7812。删掉序号要求后，模型开始用「资料未说明」**顶替实答**——q05、q08、
q12 三题从正常作答变成"资料未说明"。

### 8.4 最终版：允许留白，但不给句式

v3b 去掉一句有歧义的话（"不要用『资料未说明』代替"本身又重复了一遍那句话术）后回到 0.8576，
但 q05、q06 仍然整题只回「资料未说明。」——而它们的参考资料明明白白写着
"客服须在 48 小时内首次响应"。

用 **2×2 因子实验**（system 旧/新 × user 旧/新，各 5 轮，temperature=0.2）定位到病根：

| system | user | q05 拒答率 | q06 拒答率 |
|---|---|---|---|
| 旧（rule5 写「其余明确写『资料未说明』」） | 旧（同样重复一遍） | **5/5** | **2/5** |
| 旧 | 新 | 0/5 | 0/5 |
| 新 | 旧 | 0/5 | 0/5 |
| 新 | 新 | 0/5 | 0/5 |

**同一句占位话术在 system 与 user 里各出现一次，模型就把它当成答案本身。** 删掉任意一半即
0/5，两半都删最稳。最终第 5 条改成「只写资料覆盖的那部分；不要为了凑完整补上资料里没有的
内容，也不要因为『只答了一半』而拒答」——**允许留白，但不给句式**。

放开之后忠实度反而最高（0.9896，16 题里 15 题满分），因为那句「资料未说明。」本身就是一句
**资料不支持的断言**，它是扣分项不是免责声明。

### 8.5 为什么忠实度涨了、相关性却略低于基线

`answer_relevancy` 0.7466 < 基线 0.7868，主要是 **q08 = 0**：

- 基线回答：编了一套 5 步流程（"1. 确认备件需求… 5. 发出备件"），资料里**没有**这些步骤；
- 最终回答：「非常用备件缺货时，需要向厂商订货，发出时间会另行通知。」

后者忠实（1.0000）且正确，但 RAGAS 的 `answer_relevancy` 先让裁判判"是否含糊其辞"，
**短回答容易被判成推诿**（该指标的已知口径问题，见第五节第 3 条）。这里选择保留短答——
在"编一套流程"和"相关性分低一点"之间，前者对知识库问答是更严重的错误。

### 8.6 迭代方法本身的两条经验

1. **别用单次评估下结论**：temperature=0.2、无 seed，同一提示词同一题会时答时拒。
   q05 的拒答率是 5/5 还是 0/5，取决于那一句占位话术在不在，**不取决于跑了几次**——
   所以判断措辞要跑**多轮 + 因子**，不要看一次输出。
2. **能照抄的句子一定会被照抄**：任何"若 X 就回复 Y"的句式都要检查 Y 会不会被当成答案或
   免责声明。自检 `check_chat.py` 现在有一条负向断言：提示词里**不允许**出现
   「资料未说明 / 资料未提及」这类可照抄的占位话术。
