# 防幻觉的分层兜底

> 结论先放这里：**幻觉没有单一解**，只能按「哪一步出错」分成几层，每层用
> 它擅长的信号去拦，并且如实承认每层拦不住什么。本文记录本项目的六道闸门、
> 它们的判据、实测依据，以及**已知的漏检面**。

---

## 1. 先分型：三种幻觉，三种兜法

把"回答不对"笼统归为幻觉，会导致所有手段都往提示词里堆。实际上它们
出在不同的环节，可用的信号完全不同：

| 形态 | 典型表现 | 根因 | 唯一可靠的信号 |
|------|----------|------|----------------|
| **A. 检索错** | 库里没有这条，召回到主题相近的另一段，模型照着答 | 召回/重排把"字面相似"当"语义相关" | 重排分数的**绝对水平** |
| **B. 检索空** | 一条都没召回到，模型凭常识作答 | 没有短路 | 候选数 = 0 |
| **C. 生成编** | 资料在手，数字/型号/日期被改写、拼接、算出来 | 7B 对抽象约束不服从 | 硬事实**逐字回查** |
| **D. 过度推断** | 数字全对，但补了资料没写的因果/建议（"可以尝试沟通缩短"） | 模型把"合理"当"有依据" | 语义蕴含（成本最高） |

本项目六道闸门覆盖 A/B/C，**D 只有部分覆盖**（见 §6）。

---

## 2. 六道闸门

| # | 闸门 | 位置 | 拦什么 | 默认 | 代码 |
|---|------|------|--------|------|------|
| 1 | 入参/库校验 | API 层 | 打错的 kb_id、空问题 | 开 | `api/v1/chat.py` |
| 2 | 逐条分数闸门 | 重排器 | 单条负分片段（无关） | 开（0.0） | `infrastructure/rerank.py` |
| 3 | **整批最高分闸门** | 重排节点 | 整批都不对题（A） | **关**（0.0） | `rag/nodes.py` |
| 4 | 空上下文短路 | 条件边 | 无候选 → 不调模型（B） | 开 | `rag/graph.py` `route_after_rerank` |
| 5 | 提示词禁令 + 拒答话术 | 生成 | 一部分 C、一部分 D | 开 | `rag/prompts.py` |
| 6 | **接地性核验** | 生成之后 | C：数字/型号/日期编造、引用越界 | **开（flag）** | `rag/grounding.py` |

**顺序很重要**：能把问题挡在模型之前的，就绝不留到模型之后。
每省下一次生成，既省 2~10 秒，也少一次编造机会（3、4 两道闸门的意义就在这里）。

---

## 3. 闸门 3：整批最高分（拦"检索错"）

### 判据

重排后取所有片段的**最高分**，低于 `RERANK_MIN_TOP_SCORE` 就当作
"这一轮整批都不对题"，清空 `ranked` → 走改写重试 / 拒答。

与闸门 2 的区别：闸门 2 是**逐条**过滤（只看单条是否负分），挡不住"主题相邻、
答案没有"这种**每条都拿正分**的情况——这正是 A 型幻觉。

### 实测（本机语料：3 篇文档 / 18 题，`bge-reranker-base` 原始 logits）

```
正样本 top1：min=1.797  中位=3.671  max=8.563   （16 条可答题）
负样本 top1：min=1.048  中位=1.048  max=1.048   （1 条；其余 5 条零召回）
→ 间隔 0.749，建议阈值 1.42
```

零召回的 5 条负样本是被**闸门 2** 挡掉的（重排给负分），说明现有闸门已经
覆盖了大部分负样本；真正漏过去的是那一条 **1.048**。

### 默认为什么是关闭的

- 只有 **1 条**负样本落在正分区间，样本量不足以定阈值；
- 交叉编码器的分数是原始 logits，换模型/换语料就漂；
- 阈值调高会误杀"问得笼统但答案确实在库里"的问题（本机最低正样本只有 1.797，
  离 1.42 很近）。

**要开必须先用你自己的负样本量一遍**：

```bash
# 每行一个问题；也可以写成「kb_id<TAB>问题」
.venv\Scripts\python.exe scripts\probe_rerank_gap.py --negative negatives.txt
```

脚本会打印两组分布，并给出三选一的结论：可分（给建议值）、间隔过窄（警告）、
重叠（**明确劝阻**：任何单一阈值都会误杀或放过）。

### 实证：同一条问题，闸门开与不开的差别

问题「备件发货可以加急吗？」（库里只有"备件 5 个工作日内发出"，没有加急）。

| | 闸门关（默认） | 闸门 1.5 |
|---|---|---|
| sources | 1 条，`售后服务制度.pdf 第4页`，rerank **1.048** | 0 条 |
| 回答 | 「……备件发货是否可以加急，取决于备件是否为常用备件。如果是常用备件，**理论上可以尝试与售后服务部门沟通，看是否能缩短 5 个工作日内的时间**……」 | 「无法从知识库中找到与该问题相关的答案。」 |
| 接地性核验 | `status=ok`（唯一的硬事实「5」在资料里） | — |

加粗那句资料里完全没有。**而闸门 6 判它 ok**——因为它的数字全对，
错在推断。这个例子同时说明了闸门 3 的价值和闸门 6 的边界。

## 4. 闸门 6：接地性核验（拦"生成编"）

### 判据

回答生成完之后，抽出其中**可证伪的硬事实**——数字、百分比、金额、日期、型号——
逐个回查是否在**本轮真正送进模型的片段**里逐字出现（归一化后）。没出现的
就是模型自己编的，没有第三种解释。

分级（宁漏勿误杀：误报的代价是运维从此不看告警）：

| 情况 | 等级 | 理由 |
|------|------|------|
| 全部命中 / 没有硬事实 | `ok` | 不适用不等于差，`coverage` 记 1.0 |
| 单个数字对不上 | `warn` | "3 个步骤"这类量词、同义改写都落这里，拦就是误杀 |
| 两个以上数字且占比过半 | `low` | 已经不是措辞问题 |
| 型号 / 日期对不上 | `low` | 这类标识编不出巧合 |
| 引用序号越界 | `low` | 引用了本轮不存在的第 5 条资料 |

### 归一化（每一条都是踩出来的）

| 归一 | 为什么 |
|------|--------|
| `1,000` ≡ `1000` | 千分位只认严格三位分组：`(?<=\d),(?=\d{3}(?!\d))` |
| `２４` ≡ `24` | NFKC；中文语料全角数字很常见 |
| `XG-8800` ≡ `xg 8800` | 去空格/连字符 + 转小写，否则同一型号被判成编造 |
| 剥掉 `[1]` | 引用序号是我们加的标注，不是模型生成的事实 |
| 剥掉 `1. 2. 3.` | 列表序号是排版。**实测误报就出在这里**：q02 的三条禁令被判成"3 个数字都是编的"，整题 `low` |
| 剥掉中文数字 | 「四十八小时」抽不出来，这是**已知漏检**（见 §6） |

### 三档动作（`GROUNDING_ACTION`）

| 值 | 非流式 | 流式 |
|----|--------|------|
| `off` | 不核验 | 不核验 |
| `flag`（默认） | 回答原样返回，`grounding.status` 标记 + 日志告警 | 同左，标记在 `done` 事件里 |
| `block` | `status=low` → 回答换成拒答话术，`blocked=true` | **退化为 flag** |

**流式为什么做不到 block**：SSE 的 token 已经逐段推给前端了，服务端
收不回来。想让 `block` 真的生效，就得改用非流式 `/chat`——这是传输方式的
约束，不是实现偷懒。

**默认为什么不是 block**：把"看起来正常、其实没依据"的回答换成"找不到"，
用户会以为知识库里没有这条，这是**信息损失**，属产品取舍而非技术正确性。
出厂只观测（报告进响应、告警进日志），攒够数据再决定要不要在某个库上开。

### 误报实测

用已保存的 18 题真实评估结果（`eval/results/20261017-180621/samples.jsonl`）
离线回放核验器：

```
18 题：status=ok 18 / 18，零误报
（其中 q02/q04 最初被判 low，正是"列表序号"这个 bug，修掉后归零）
```

## 5. 提示词这一层（闸门 5）

这层的判据与踩坑细节写在 `rag/prompts.py` 的模块文档里，这里只留结论：

- 抽象要求（"不要编造"）对 7B 无效，要**逐条编号禁令**；
- **正面要求必须是无条件祈使句**，条件句（"若资料带标注则…"）会被当成不成立；
- **允许留白但不给句式**：写"其余写「资料未说明」"会让模型把占位话术当答案
  （q05 整题只回五个字）；
- 效果：忠实度 0.902 → **0.9896**，命中率 1.000 保住；代价是回答更短、
  `answer_relevancy` 略降（该指标惩罚简洁，不是判它无关）。

可见提示词能买到 9 个百分点，但**买不到"零编造"**——所以还需要闸门 6。

## 6. 已知的漏检面（诚实清单）

| 漏检 | 为什么拦不住 | 现在的兜法 |
|------|--------------|-----------|
| **过度推断（D 型）** | 数字全对，语义上多推了一步。硬事实核验查不出来 | 只能靠提示词第 3、4 条；再用闸门 3 减少"拿错资料"的机会 |
| 中文数字 | 「四十八」不是阿拉伯数字，抽不出来 | 未处理。做中文数字转换会引入大量歧义（"一半"、"数十"），收益不抵误报 |
| 同义改写 | 「48 小时」→「两天」 | 同上。这类改写多数**是**对的，拦它反而伤可用性 |
| 长段照抄错位 | 回答把 A 文档的段落说成 B 文档的 | 结构化 citations 给的是"本轮用了哪几片"，不做逐句归因 |
| 跨文档冲突 | 两篇文档写不同数字，模型任选其一 | 未做一致性检测。正确做法是入库阶段标版本/生效日期，属数据治理 |

**语义级核验（NLI / LLM-as-judge）为什么不默认开**：能抓 D 型，但每次问答
多一次模型推理（本机 7B 约 2 秒），且流式路径同样**追不回已经发出的字**。
要用应该先做对照实验（同一批题、人工标注 30 条 D 型错误，量它的召回与误报），
而不是直接打开。**本项目尚未做这个实验，因此不提供该开关。**

## 7. 运营：怎么用这些信号

### 看什么

```bash
# 非流式：响应体里直接有
{
  "answer": "...",
  "grounding": {"status": "low", "checked": 3, "unsupported": ["XG-9999"],
                "invalid_refs": [], "coverage": 0.667, "blocked": false,
                "warnings": ["回答里出现资料中不存在的型号/日期：['XG-9999']"]}
}

# 流式：done 事件里（token 已发，只能事后标记）
event: done
data: {"answer": "...", "grounding": {...}, ...}

# 当前处于哪一档（前端不要抄默认值）
GET /api/v1/chat/options  ->  {"grounding_action": "flag", ...}
```

日志关键字：`回答接地性告警`（flag 档命中）、`接地性核验未通过，降级为拒答`（block 档命中）、
`重排最高分 ... 低于整批闸门`（闸门 3 命中）。

### 怎么定阈值

1. 攒一周的 `status=low` 样本，人工看是真编还是误报；
2. 误报多 → 检查是不是列表序号/中文数字/同义改写的变体，补归一化规则；
3. 真编多 → 先调提示词（成本最低），再考虑 `block`；
4. 开 `block` 前后各跑一次评估集，比较 `answer_relevancy` 与拒答率的差值
   —— **拒答率上升是 block 的必然代价，不是 bug**。

### 自检

```bash
.venv\Scripts\python.exe scripts\check_grounding.py    # 45 项，不需要任何外部依赖
.venv\Scripts\python.exe scripts\probe_rerank_gap.py   # 需要 Milvus + BGE，不需要 LLM
```
